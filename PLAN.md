# План развития jtsx-loader

Дополнение 2026-10-05 по отдельному поручению: реализованы экранирование по умолчанию, raw()/renderToString(), регистрация из JS, миграционный legacy-режим и обновление существующего сайта example на / и /ru. Это отдельное согласованное изменение контракта, а не завершение всех этапов 2–4. Статический docs-site, типы/CI и скачиваемые бойлерплейты исходного плана остаются отдельными задачами. Новый API помечен Unreleased, без повышения версии и публикации.

Актуализация 2026-10-05: материалы перенесены из ветки `private` в `master`. Версия `0.1.18` опубликована в npm с тегом `latest`. Этап 1 и обновление совместимости Node.js реализованы; этапы 2–4 не начаты. Ниже сохранены исходный план и датированные результаты проверок; сведения об отсутствии публикации относятся к моменту соответствующей проверки.

Дата: 2026-09-11. База аудита: версия 0.1.15, коммит 71dd852.
Состояние: этап 1 завершён 2026-09-11; остальные этапы не начаты.

Цель: исправить ошибки, сохранить работоспособность существующих проектов и подготовить удобный вход для новых пользователей.

## Общие правила

- [Контракт совместимости](plans/COMPATIBILITY.md) фиксирует старое поведение, допустимые исправления и новые режимы. Это источник решений для загрузчика и фабрики.
- [Порядок работы](plans/WORKFLOW.md) задаёт небольшие шаги, объём контекста, выбор проверок и сохранение прогресса. Он предназначен в том числе для исполнителя с меньшим reasoning.
- Каждый этап содержит задачи с постоянными идентификаторами, ожидаемые результаты и критерии завершения. Отметка в чекбоксе означает, что результат проверен.
- Выполнять этапы, порученные пользователем. Если поручен один этап, завершить его и отчитаться. Если поручены все этапы, переходить дальше после прохождения критериев; отдельное подтверждение на каждый шаг не требуется.
- Создание этих файлов не запускает реализацию, выпуск npm-пакета или публикацию сайта.
- Версию, диапазон Node.js и публичные пути не менять попутно. Коммиты и публикации выполнять только в пределах отдельного поручения на эти действия.
- Генерация писем, SMTP и email-бойлерплейт исключены. Вместо них нужен Fastify SSR.
- Новые runtime-возможности отделять от старого режима явным подключением. Нельзя одновременно обещать прежний HTML и незаметно включить всем автоматическое экранирование.

## Исходное состояние на момент аудита и границы доказательств

- На момент аудита автоматического набора тестов и CI не было; example/pages/test.jsx — демонстрационная страница. На этапе 1 добавлены регрессионные тесты и проверка установленного архива; CI остаётся в этапе 2.
- В текущем окружении проверены Node.js 22.14.0 и Windows. Поддержка других версий и ОС ещё не проверена этим аудитом.
- В аудит входили отдельные сценарии загрузки/рендера, HTTP-проверка демо и npm pack --dry-run. Это не полная проверка всех пользовательских проектов.
- Обнаружено использование --import jtsx-loader, ?reload и прямого пути к фабрике в существующих локальных потребителях. Полный запуск этих проектов не проводился.
- Старый режим останется с документированными ограничениями: сырые строки children, отсутствие автоматического ожидания вложенных async-компонентов и рост ESM-кэша при ?reload. Наличие новых режимов не означает исправления этих ограничений в старом режиме.

## Дополнение 2026-10-03: современные версии Node.js

Выполнено по отдельному поручению пользователя; этапы 2–4 не запускались.

Причина: Node.js 26 помечает module.register() как deprecated, а engines исключал версии >=25. Решение: снять только верхнюю границу (>=20.16); в loader/register.mjs выбирать registerHooks по наличию функции, иначе сохранить register. Для нового API добавлен синхронный адаптер; URL/reload и трансформация вынесены в общий loader/hooks.mjs, старый loader/loader.mjs сохраняет async-интерфейс. Опции трансформации, как раньше, считываются один раз. Публичная команда, пути, настройки и правила рендера сохранены.

Проверки окончательного кода на Windows:

| Node.js | Проверка | Результат |
| --- | --- | --- |
| 20.16.0 | registration, loader, compat, async-factory, renderer | 33 passed; 1 неприменимый тест sync hook chaining пропущен: API отсутствует |
| 22.14.0 | Тот же набор, старая регистрация | 33 passed; тот же 1 неприменимый тест пропущен |
| 22.15.0 | Тот же набор, первая 22.x с registerHooks | 34/34 |
| 24.19.0 | Тот же набор, синхронная регистрация | 34/34 |
| 26.10.0 | npm test, включая HTTP/nodemon | 38/38 |
| 26.10.0 | npm run test:package | Установка настоящего архива и оба режима рендера прошли; 43 файла, новые адаптеры включены |

Команда целевого набора для выбранного исполняемого файла Node: --test tests/registration.test.mjs tests/loader.test.mjs tests/compat.test.mjs tests/async-factory.test.mjs tests/renderer.test.mjs. Регрессионный тест с --throw-deprecation сначала воспроизвёл DEP0205 на 26.10, после изменения прошёл. Версии 20.16/22.15 проверялись временными официальными бинарниками с проверкой SHA256; системный Node не переключался. Для 20.16 ограничения Windows-песочницы потребовали повторного запуска вне неё: первоначальный EPERM происходил до загрузки проекта. Другие ОС и будущие версии не проверялись. Версия пакета 0.1.15 не изменена; публикации нет.

## Как начать отдельную задачу

Пример поручения для одного небольшого изменения:

> Выполни шаг S1.1 из plans/STAGE_1_CRITICAL_FIXES.md. Начни с PLAN.md и plans/WORKFLOW.md, соблюдай plans/COMPATIBILITY.md. Проверь результат и обнови карточку этапа. Остальные шаги пока не выполняй.

Пример поручения для целого этапа:

> Выполни этап 1 по plans/STAGE_1_CRITICAL_FIXES.md, последовательно проходя его шаги. Сохрани совместимость по plans/COMPATIBILITY.md. После проверок обнови статусы и сообщи о фактическом результате. Не повышай версию и не публикуй пакет.

API и команды этапа 1 опубликованы и описаны в [README.md](README.md) и [CHANGELOG.md](CHANGELOG.md). Остальные этапы описывают будущую реализацию. Перед использованием названных файлов и команд проверять их наличие и карточку соответствующего этапа.
