# Контракт совместимости

## Изменение по поручению пользователя 2026-10-05

Пользователь явно поручил экранирование по умолчанию, raw(), запуск без --import и обновление документации. Это разрешает смену defaults и типа результата, обсуждённую до реализации. Новые правила имеют приоритет над историческим контрактом ниже:

- escapeChildren/escapeAttributes по умолчанию true. JSX-теги и фрагменты возвращают доверенную неизменяемую обёртку; renderToString() превращает её в HTML на границе вывода. Простая строка всегда считается текстом. raw() явно помечает доверенный HTML.
- Новый режим рекурсивно нормализует массивы без разделителей, пропускает boolean/null/undefined, сохраняет 0 и bigint. Компоненты получают исходные props; экранирование выполняется при сериализации. __raw/__escape сохраняются.
- Старые ожидания K2 остаются тестами режима escapeChildren:false + escapeAttributes:false. Публичные deep paths и --import сохраняются. Wildcard exports сохраняет доступ ко всем прежним путям и позволяет self-import.
- Новый register.js и импорт корня пакета разрешают регистрацию из JS с последующим динамическим импортом. runtime.js не регистрирует hooks и подходит для конфигурации.
- Версия не повышена, публикация не запрошена. README/сайт явно помечают новый контракт как Unreleased.

Причина: невозможно различить пользовательский текст и готовую JSX-разметку, если оба значения являются обычными строками. Решение: отдельная обёртка, явная граница вывода и сохранённый legacy-режим.

[Общий план](../PLAN.md). База: jtsx-loader 0.1.15, коммит 71dd852; проверено в аудите 2026-09-11 на Windows/Node.js 22.14.0.

Документ фиксирует поведение для регрессионных тестов. Этап 1 проверен 2026-09-11 на Node.js 22.14.0/Windows; полной проверки всех пользователей нет. «Legacy» ниже означает существующие настройки и существующую фабрику без новых опций.

## K1. Публичная поверхность

- Запуск: node --import jtsx-loader app.js; ESM; существующий main остаётся совместимым.
- Пути: loader/register.mjs, loader/loader.mjs, factory/jsxFactory.js, factory/jsxUtils.js, factory/utils.js, factory/possibleAttributes.js, package.json и другие ранее поставлявшиеся файлы. Не удалять и не закрывать их попутно.
- Экспорты фабрики: _jsx, _jsxFragment, _jsxUtils. У jsxUtils.js сохранить default-объект и именованный escapeHtml; у utils.js — именованные функции.
- Существующая _jsx синхронно возвращает строку для HTML-тега; при вызове функции-компонента возвращает её результат. Не превращать этот путь в async-функцию.
- Поиск jtsx.config.js по process.cwd(); существующие ключи importFactory, esbuildTransformConfig, attributeParser, disableAttrWarnings, rewriteReactAttrs сохраняются.
- Поддержку .jsx/.tsx, делегирование других расширений Node и поведение ?reload не заменять без явного выбора нового режима.
- По явному поручению пользователя от 2026-10-03 снята верхняя граница engines: >=20.16 вместо >=20.16 <25. Прежний минимум сохранён. Разные требования новых dev-инструментов или шаблонов не дают основания молча поднять минимум ядра.
- Публичный --import выбирает registerHooks по наличию API (22.15+/23.5+), иначе использует register, включая ранние 22.x. Новый адаптер синхронный; старый loader/loader.mjs сохраняет async-экспорты. Конфиг ожидается до установки новых hooks; число его выполнений зависит от контекста Node.js, однократное выполнение не гарантируется.

## K2. Точные примеры старого поведения

Перенести эти примеры в тесты. Пробелы, типы результата и порядок частей важны. Значения в таблице — реальные результаты аудита, а не желаемый новый HTML.

| Вход | Legacy-результат |
| --- | --- |
| `_jsx('p', null, 'hello')` | `<p>hello</p>` |
| `_jsx('p', null, '<b>hello</b>')` | `<p><b>hello</b></p>` |
| Два JSX-sibling: b(A), i(B) внутри p | `<p><b>A</b><i>B</i></p>` |
| Массив `['A', 'B']` внутри p | `<p>A B</p>` |
| Фрагмент из `'A', 'B'` | `A B` |
| Функция-компонент без children / с одним / с двумя | `children: []` / `'A'` / `['A', 'B']` |
| input: disabled=true, required=false, id=undefined, title=null | `<input disabled="true" id title="null"/>` |
| `className` | Преобразуется в `class` |
| Другие React-имена | По умолчанию предупреждение; замена только при rewriteReactAttrs=true |
| __raw и __escape одновременно с children | Порядок: children → __raw → __escape |
| p: `child='A'`, `__raw='<b>B</b>'`, `__escape='<i>C</i>'` | `<p>A<b>B</b>&lt;i&gt;C&lt;&#x2F;i&gt;</p>` |
| __escape=0 | Старый режим не выводит значение; не менять незаметно |
| Фрагмент с единственным false | Возвращается boolean false |
| attributeParser.ac(attribute, value) | Возвращённая строка HTML-атрибута вставляется как раньше |

Дополнительно фиксируются неизвестные атрибуты, style-строка/объект с нативными CSS-именами, void-теги, прямые вызовы компонентов, статический и динамический import, пользовательская фабрика и обычные JS/JSON/builtin-импорты.

## K3. Разрешённые узкие исправления старого режима

Эти исключения из точного сохранения поведения должны иметь отдельные регрессионные тесты и запись в CHANGELOG:

1. escapeHtml: обратная косая черта сохраняется, вместо ошибочного `&undefined;`. Экранирование остальных символов, включая прямую косую черту, сохраняется.
2. Фрагмент с null даёт пустую строку вместо исключения. Поведение false, undefined, обычных массивов и одиночных строк не нормализовать заодно.
3. style=null не создаёт атрибут и не вызывает исключения. Другие значения атрибутов сохраняют правила K2.
4. Файловый импорт .jsx/.tsx с hash обрабатывается загрузчиком; query/hash сохраняют свою роль в идентичности ESM-модуля.
5. Диагностика показывает правильный файл/позицию и исходную причину. Ошибка не превращается в успешный пустой модуль.
6. Неисправный конфиг выдаёт предупреждение вместо полного молчания; старое продолжение с defaults сохраняется, если строгий режим не включён.

Прочие различия HTML и результата функций требуют нового явно подключаемого режима. Автоматическое обновление всех snapshots запрещено.

## K4. Зафиксированные новые возможности

Этот API реализован в рабочем дереве на этапе 1 и описан в CHANGELOG как Unreleased. Версия package.json остаётся 0.1.15; новая версия не опубликована. В исходной 0.1.15 этих возможностей нет.

| Возможность | Без новой настройки | Явное подключение |
| --- | --- | --- |
| injectFactory | 'legacy': прежнее условие !esbuildTransformConfig | true: добавить importFactory независимо от transform options; false: никогда не добавлять |
| escapeAttributes | false: прежние строковые атрибуты | true: экранировать обычные значения при сериализации атрибутов |
| JTSX_STRICT_CONFIG | Не задано: warning и прежние defaults при неисправном конфиге | Значение 1: неисправный существующий конфиг завершает запуск с ошибкой |
| factory/asyncFactory.js | Прежняя factory/jsxFactory.js | Указать новый путь в существующем importFactory; использовать await Page(props) |

### Правила подключения фабрики

- При отсутствии injectFactory действует точно прежнее условие. Так не ломаются проекты с ручным импортом или своей jsxFactory.
- Случай esbuildTransformConfig={} исправляется явным injectFactory=true. Не утверждать, что старый вариант этого конфига теперь работает без изменения настроек.
- Не разбирать JSX регулярными выражениями, чтобы угадывать наличие ручного импорта. Конфликт ручного импорта и явно включённой инъекции должен давать понятную ошибку компиляции.

### Граница экранирования

- escapeAttributes=true принимает обычные, заранее не экранированные значения. Как минимум &, двойная кавычка, < и > не могут выйти из quoted attribute.
- attributeParser пока возвращает доверенную сырую строку: нельзя экранировать целиком возвращённый фрагмент и считать это защитой. Новый callback-пример должен экранировать именно значение.
- Children-строки и __raw остаются сырым HTML в обеих фабриках. Недоверенный текст передавать через __escape или escapeHtml.
- Этот режим не является HTML-санитайзером, проверкой URL-протоколов или безопасной сериализацией JavaScript внутри script. Эти границы описать рядом с примерами.

### Правила asyncFactory

- Новый файл экспортирует _jsx, _jsxFragment, _jsxUtils и подключается через уже существующую настройку importFactory. Старые экспорты не заменять.
- Рендер нового режима возвращает `Promise<string>`. Ожидать компоненты и children рекурсивно, включая массивы; сохранять исходный порядок.
- В новом режиме null/undefined/boolean children пропускаются, числа сохраняются, массивы рекурсивно объединяются без неявных разделителей. Пробел задаётся текстом шаблона.
- Для функции-компонента после разрешения и нормализации children: ноль → [], один → значение, несколько → массив. Ошибка дочернего компонента должна отклонять итоговый Promise и ловиться внешним await.
- __escape=0 и __raw=0 в новом режиме дают текст 0; null/undefined payload отсутствует. Для прочих scalar payload применяется преобразование в строку. Legacy-поведение K2 сохраняется.
- Не добавлять streaming, hydration, React runtime, автоматическое экранирование всех строк или исполнение событий в браузере.

### Строгий конфиг

Используется переменная окружения, а не свойство внутри конфига: синтаксически неисправный файл не может сообщить собственный strictConfig. Полностью отсутствующий jtsx.config.js допустим в обоих режимах. Ошибка вложенного импорта не считается отсутствием самого конфига. Учесть отдельный контекст loader hooks: общая функция чтения не гарантирует одно выполнение конфигурации на весь процесс.

## K5. Перезагрузка и публикация

- ?reload сохраняет прежнюю семантику, включая обновление зависимостей. Не заменять его константой ?v=1 и не обещать освобождение ESM-кэша.
- Новые бойлерплейты используют restart процесса в dev и обычные импорты в production. Новый worker reload не входит в эти четыре этапа.
- Рефакторинг не добавляет ограниченный exports. Если это понадобится отдельной задачей, сначала перечислить и сохранить все прежние пути.
- npm pack проверять до и после изменения правил включения файлов. Новые tests/plans/templates/docs-site можно не поставлять с ядром; ранее доступные файлы не удалять попутно.
- Рост памяти из аудита (~9 МБ после 150 дополнительных импортов) относится только к синтетическому примеру. Не использовать его как бюджет или benchmark для пользовательского сервера.
